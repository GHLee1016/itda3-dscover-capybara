## 2. 대회 목적 및 배경

- 상품 뒷면 이미지에서 소비기한을 **가장 정확하고 효율적으로** 추출하는 OCR 아키텍처를 설계하고, 이를 실제 산업 도메인에 어떻게 적용할지 기획하는 대회.
- 단순히 모델을 돌리는 것을 넘어 **"왜 이 아키텍처가 필요한가?"** 를 논리적으로 설계·입증하는 것이 목표.
- 정확도 소수점 경쟁에 매몰되지 않고 **[정확도 + 처리 속도 + 서버/운영 비용 + 도메인 활용성]** 을 종합 고려하는 엔지니어링 사고를 요구.

### 진행 방식

| 단계 | 내용 |
| --- | --- |
| 예선 | 라벨링 없는 상품 뒷면 사진 3,352장 제공 → 사진 속 여러 숫자 중 **정확한 소비기한 날짜만** 추출 |
| 본선 | 예선에서 개발한 OCR 기술을 실제 산업 현장에 적용·운영하는 종합 기획 (시스템 운영 아키텍처 설계 ~ 비즈니스 손실 절감 ROI 기획) |

### 평가 관점 (4대 키워드)

- **논리성** — 모델링 및 기술 선택의 근거를 논리적으로 설명할 수 있는가?
- **적극성** — 라벨링 규칙을 직접 정의하고, 필요시 데이터를 직접 수집·확장했는가?
- **정확성** — 제한된 CPU 환경에서 빠른 속도와 높은 날짜 추출 정확도를 달성했는가?
- **주체성** — 기술의 활용처와 운영 방식을 주도적으로 정의하고 기획했는가?

## 7. 제출 파일 구조

베이스라인 코드는 제공되지 않으며, 참가자가 직접 추론 파이프라인과 `predict.ipynb`를 구축해야 함.

```
itda3-{학회영문}-{영문팀명}/
├── predict.ipynb              # 메인 추론 노트북 (운영진 채점용, 필수)
├── requirements.txt           # 실행 환경 패키지 목록 (필수)
├── README.md                  # 가중치 다운로드 및 실행 가이드 (필수)
├── download_weights.sh        # [선택] 외부 가중치 다운로드 스크립트
├── notebooks/                 # [선택] 실험·분석 노트북 (채점 대상 아님)
└── weights/                   # [선택] 모델 가중치 저장 폴더
```

### `predict.ipynb` 작성 규칙

채점 대상 파일은 **`predict.ipynb` 단 하나**. 실험용 노트북은 `notebooks/`에 자유롭게 두되 채점하지 않음.

**① 첫 번째 코드셀은 반드시 아래 형태의 설정 셀**

```python
# ===== CONFIG =====
import os
INPUT_DIR   = os.environ.get("ITDA_INPUT_DIR",  "./val_images")
OUTPUT_PATH = os.environ.get("ITDA_OUTPUT_PATH", "./submission.csv")
# ==================
```

- 운영진은 환경변수 `ITDA_INPUT_DIR` / `ITDA_OUTPUT_PATH`만 주입 후 노트북을 순차 실행
- `os.environ.get` 형태를 **그대로 유지**. 값을 직접 대입하면 주입이 무시되어 채점 불가

**② 실행 방식: 위에서 아래로 전 셀 순차 실행 (Run All)**

- 셀 순서 = 실행 순서. 위 셀이 아래 셀 결과에 의존하지 않도록 작성
- `input()`, `getpass` 등 **사용자 입력 대기 코드 금지** → 타임아웃 처리됨
- 노트북 출력(output) 저장 여부는 채점에 영향 없음

**③ 최종 셀은 `OUTPUT_PATH`에 `submission.csv` 저장**

- 인덱스 반드시 제외: `df.to_csv(OUTPUT_PATH, index=False)`
- 인덱스 포함 시 컬럼이 밀려 자동 채점기 파싱 에러(0점) 발생 가능
- 실행 후 파일이 없거나 비어 있으면 **정량 60점 → 0점**

**④ 제출 전 자가 검증 권장**

```bash
ITDA_INPUT_DIR=/tmp/test_imgs ITDA_OUTPUT_PATH=/tmp/out.csv \
  jupyter nbconvert --to notebook --execute predict.ipynb \
  --output /tmp/executed.ipynb
```

에러 없이 완료되고 `/tmp/out.csv`가 생성되어야 함.

### 운영진 채점 실행 명령

```bash
export ITDA_INPUT_DIR=/eval/val_images
export ITDA_OUTPUT_PATH=/eval/submission.csv

jupyter nbconvert --to notebook --execute predict.ipynb \
    --ExecutePreprocessor.timeout=2400 \
    --output /tmp/executed.ipynb
```

> ⚠️ `ITDA_INPUT_DIR`은 매 채점마다 **비공개 평가 데이터셋(Unseen Test Data)** 경로로 주입됨.
> - 배포된 3,352장 외에 운영진 자체 구축 검증셋으로 채점
> - `./data`, `/content/drive` 등 **로컬 경로 하드코딩 시 정량 0점**
>
> ⚠️ `requirements.txt`에 **`nbconvert`, `ipykernel` 포함 필수**

### GitHub 저장소 필수사항

- `predict.ipynb` — Run All만으로 `submission.csv` 단독 생성
- **모델 가중치**
  - `.pt`, `.pth`, `.safetensors` 등 대용량 파일 **Git 직접 커밋/푸시 금지** (`.gitignore` 등록 필수)
  - 제공 방식: GitHub Release Assets 첨부 / 외부 링크(Google Drive·HuggingFace) + `download_weights.sh` 또는 코드 내 자동 다운로드 로직
- `requirements.txt` (또는 `environment.yml`) — 재현을 위한 **정확한 패키지 버전** 명시
- `README.md` — 가중치 다운로드 안내, 환경 구축 방법, 추론 실행 방법

## 8. 출력 파일 스키마 (`submission.csv`)

| --- | --- | --- | --- | --- |
| 1 | 2026 | 05 | 29 | 2026-05-29 |

- `image_id`: 확장자를 제외한 이미지 파일명 (예: `1`)
- `year`: 4자리 연도 문자열 (예: `2026`, 미인식 시 `NONE`)
- `month`: **2자리** 월 문자열 (예: `05`, 미인식 시 `NONE`)
- `day`: **2자리** 일 문자열 (예: `29`, 미인식 시 `NONE`)
- `final_date`: 연·월·일을 하이픈으로 연결 (예: `2026-05-29`, 미인식 시 `NONE`)

**이메일 본문 템플릿**

```
1. 팀명: [학회명]_팀명 (예: [CODE]_소비기한선발대)
2. 팀원 이름: 홍길동(대표자/팀장), 김철수, 이영희
3. GitHub Repository URL: https://github.com/username/repository
4. 최종 제출 Commit Hash: a1b2c3d4e5f6... (git rev-parse HEAD 실행 결과값)
5. 첨부파일: [CODE]_소비기한선발대_아키텍처구조도.pdf
```

**아키텍처 구조도·설계 요약서 (PDF 2장 이내)**

- 파일명: `[학회명_팀명]_아키텍처구조도.pdf`
- **1페이지**: 전체 파이프라인 아키텍처 구조도
- **2페이지**: 설계 논리 및 최적화·활용 전략
  - 모델/규칙 설계 의도 및 기술 선택의 논리적 이유 (왜 이렇게 설계했는가?)
  - 제한된 CPU 환경에서의 속도/오탐 최적화 전략
  - 추후 활용 계획 (활용 방안 및 확장성)

### 2차 본선 — 10월 2일(금) 23:59 마감 (상위 8팀)

## 12. FAQ

**Q. 3,352장 Unlabeled 데이터를 전부 수동 라벨링해야 하나요?**
A. 아닙니다. 정규식/OCR 기반 룰로 자동 라벨을 생성하거나, 예외 케이스 일부만 수동 라벨링해 학습시키는 등 주체적 전략을 활용하면 됩니다.

**Q. 본선 도메인 기획은 무엇을 의미하나요?**
A. 설계한 OCR 아키텍처를 '편의점 유통기한 관리', '식품 기부 푸드뱅크', '물류창고 입출고 자동화' 등 특정 기업/산업에 실제 도입한다고 가정하고, 서버/온디바이스 운영 구조 및 예상 비용을 산출하는 기획입니다.

**Q. 본선 발표 운영 및 시간 배분은?**
A. 총 8개 팀 진출, 팀당 15분 (발표 10분 + Q&A 5분).
