## 3. 핵심 설계 한 줄

**각 칸은 앞 칸이 실패한 이미지에만 돕니다.** 그래서 칸을 추가해도 이미 맞힌
답이 깨지지 않습니다 — 회귀 위험이 구조적으로 0입니다. 덕분에 수단 12가지를
공격적으로 시험해 5가지만 남겼습니다.

```
1칸 RapidOCR det small @1024px     80% 여기서 끝
2칸 adaptive 이진화                 2%
3칸 det medium                     5%
4칸 CLAHE + det medium             1%
5칸 인식기 교체 — 한국어             1%
6칸 인식기 교체 — 영문               1%
7칸 도트 전용 판독기 (직접 학습 CTC)  1%
보조 YOLO 검출 + PP-OCR (최후수단)   1%
   → 날짜 규칙 엔진 → year/month/day (확신 없으면 NONE)
```

## 4. ⚠️ 코드를 직접 돌릴 거면

**저장소를 한글이 들어간 폴더에 두지 마세요.** PaddleOCR의 C++ 백엔드가
비ASCII 경로의 모델을 못 엽니다. 그래서 보조 경로가 **에러 없이** 꺼지고
정확도만 조용히 내려갑니다. 자동 우회를 넣어 뒀지만 ASCII 경로(`C:\itda` 등)가
가장 확실합니다.

```powershell
bash download_weights.sh          # 가중치 (인터넷 필요, 1회)
python run_local.py --n 30        # 30장으로 확인
```

실행 로그에서 이 줄을 확인하세요.

```
보조    PP-OCRv3 + YOLO       bundled      ← '로딩 실패' 면 경로 문제
```

## 6. 발표에서 제일 강한 부분

**병목을 두 번 잘못 짚었고 두 번 다 측정으로 잡아냈습니다.** 보고서 4-3절입니다.

1. **도트 인쇄가 문제라고 봤는데** 전체에서 재니 도트가 오히려 더 잘 읽혔습니다
   (97.0% 대 95.9%). 육안으로 눈에 띄는 것과 원인은 다릅니다.
2. **그럼 검출이 병목이라고 봤는데**(96.1% 대 85.8%, −10.2%p) 검출 문턱을 낮춰
   **검출을 강제로 성공시켰더니 정확도가 안 움직였습니다**(92.3%→92.2%).
   상관을 인과로 읽은 것이었습니다.

> 쓸 문장: **"하위 그룹의 성능 차이는 그 자체로 원인을 지목하지 않는다.
> 원인이라 주장하려면 그 변수를 직접 조작해 결과가 따라오는지 봐야 한다."**

기각한 것이 채택한 것보다 많다는 점도 같이 보여주면 좋습니다
(`03_기각목록_rejected_rungs.py`).
