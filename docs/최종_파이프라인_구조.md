# 최종 파이프라인 구조

지금 제출물(`predict.ipynb`)이 이미지 한 장을 어떻게 처리하는지만 적은 문서입니다.
왜 이렇게 됐는지의 과정은 `파이프라인_설명.md`를 보세요.

---

## 0. 한눈에

```
이미지 파일
   ↓  imread_any()            한글 경로 대응 디코딩
   ↓  downscale_max(1024)     긴 변 1024px로 축소
   ↓
CombinedPipeline.predict()
   ├─ _rapid()      주력 + 재시도 계단 6칸
   ├─ _fallback()   위가 전부 실패했을 때만
   └─ 그래도 없으면 전부 NONE
   ↓
to_row()  →  submission.csv 한 행
```

입력은 `ITDA_INPUT_DIR`의 이미지, 출력은 `ITDA_OUTPUT_PATH`의 CSV입니다.
두 환경변수 모두 노트북 첫 CONFIG 셀에서 읽습니다.

---

## 1. 재시도 계단 — `_rapid()`

`src/combined.py` 244~372행. 파이프라인의 본체입니다.

칸을 순서대로 오르다가 **온전한 날짜**(연·월·일이 모두 채워진 것)를 낸 첫 칸에서
멈추고 그 값을 돌려줍니다.

| 칸 | 입력 이미지 | 엔진 | 처리 비율 |
|---|---|---|---:|
| 1 | 1024px 원본 | det small + rec small | **82%** |
| 2 | adaptive threshold | det small + rec small | 1% |
| 3 | 1024px 원본 | **det medium** + rec small | 2% |
| 4 | CLAHE 적용 | **det medium** + rec small | 1% |
| 5 | 1024px 원본 | det small + **rec 한국어** | 실패분 |
| 6 | 1024px 원본 | det small + **rec 영문** | 실패분 |
| 7 | 640px | 보조 경로 (아래 3장) | 2% |

각 칸이 쓰는 전처리는 이렇습니다.

- **adaptive threshold**: `cv2.adaptiveThreshold(gray, 255, GAUSSIAN_C, BINARY, 31, 11)`
- **CLAHE**: `clipLimit=3.0, tileGridSize=(8,8)` 로 국소 대비를 올림.
  잉크가 옅거나 도트 프린터로 점이 끊긴 인쇄에 효과가 있습니다.
- **rec 한국어 / 영문**: 검출기는 그대로 두고 **인식기만** 교체합니다.
  주력 인식기가 중국어 모델이라 한글이 날짜에 붙어 있으면 같이 깨지는데,
  이 두 칸이 그걸 살립니다.

### 반쪽짜리 결과의 처리

각 칸은 **온전한 날짜만** 성공으로 칩니다. 연·월·일 중 일부만 읽힌 결과
(`NONE-03-11` 같은 것)는 `partial` 변수에 **모아 두기만** 하고 계단을 계속 오릅니다.
어느 칸도 온전한 날짜를 못 내면 그제야 모아 둔 첫 번째 반쪽짜리를 씁니다.

```python
partial = None

def keep_partial(texts):
    nonlocal partial
    if partial is None and texts:
        p = self.rules.extract_partial_date(texts)
        if p is not None:
            partial = p
```

`_full()`은 온전한 날짜만 돌려주고, `_from_texts()`는 반쪽짜리도 돌려줍니다.
계단 안에서는 `_full()`만 씁니다.

## 2. 날짜 판별 — `choose_expiration_date()`

`src/team2_rules.py` 26~830행. OCR이 낸 텍스트 조각 목록을 받아
`YYYY-MM-DD` 문자열 하나를 돌려줍니다. 못 찾으면 `None`.

### 2-1. 후보 문자열 만들기 (36~66행)

OCR은 `2022`와 `02.14`를 다른 줄로 끊는 일이 잦습니다. 그래서 각 조각에 대해
**원문 / 인접 2개 이어붙임 / 인접 3개 이어붙임**을 모두 후보로 넣습니다.

```
조각 3개  →  후보 최대 9개
```

### 2-2. 날짜 패턴 추출 (159~770행)

각 후보에서 정규식으로 날짜를 뽑습니다. 유효 연도는 **2015~2035**이고,
`datetime()` 생성에 실패하는 날짜(2월 30일 등)는 버립니다.

| 패턴 | 모양 | 예 |
|---|---|---|
| A | `YYYY.MM.DD` | `2022.12.02` |
| A-1 | `YYYY.MMDD` | `2021.1117` |
| A-2 | `YYYYMM.DD` | `202512.20` |
| B | `DD.MM.YYYY` | `24/12/2021` |
| B-2 | `DD MM YYYY` | `21 11 2022` |
| C | `YYYY MON DD` | `2021/JUN/14` |
| D | `MON DD YYYY` | `JUN 08 2018`, `DEC.25.2021` |
| E | `DD MON YY` | `31JUL21` |
| E2 | `DD MON YYYY` | `01 SEP 2023` |
| E3 | `MON DD YY` | `JUL 22 21` |
| F | 2자리 연도 구분자 | `17.12.20`, `24/12/21` |
| G | 공백 구분 2자리 | `09 11 22` |
| H | 구분자 없음 | `20251220`, `251220` |

**A 패턴에는 시각 차단이 붙어 있습니다.** 구분자에 공백이 포함돼 있어서
`2026.08` + `22:14`가 `2026-08-22`로 읽히던 문제가 있었고, 일(日) 자리 뒤에
`:숫자`가 오면 받지 않도록 `(?!\s*:\s*\d)`를 넣었습니다.

**F 패턴의 2자리 연도는 한국식이 기본입니다.** `24/11/21`처럼 어느 자리가
연도인지 모호할 때 `YY.MM.DD`로 읽습니다.

### 2-3. 점수 매겨 고르기 (771~830행)

후보마다 주변 텍스트를 보고 점수를 줍니다.

| 가중치 | 대상 |
|---:|---|
| **+15** | `까지` |
| **+10** | `소비기한` `유통기한` `EXPIRY` `EXP DATE` `EXP:` `BEST BEFORE` `BEST BY` `BEST IF USED BY` `USE BY` `BB:` |
| **+4** | `EXP` `BB` (약한 신호) |
| **−8** | `부터` |
| **−12** | `제조일` `생산일` `포장일` `MFG` `PROD` `PACKED` `PD:` 등 |

정렬은 `(점수, 날짜)` 내림차순입니다. **점수가 같으면 늦은 날짜**를 고릅니다.
제조일자와 소비기한이 함께 찍힌 경우를 이 둘이 처리합니다.

마지막으로 **최고 점수가 음수면 `None`을 돌려줍니다.** 제조일자만 있는 이미지에서
그걸 소비기한으로 내보내지 않으려는 장치입니다.

### 2-4. 부분 날짜 — `extract_partial_date()` (833행~)

`choose_expiration_date()`가 실패했을 때만 부릅니다. 연도가 없거나 일이 없는
표기를 건집니다.

| 패턴 | 모양 | 결과 |
|---|---|---|
| A | `MM/YYYY` | `2021-12-NONE` |
| A-1 | `MM/YY` | 〃 |
| A-2 | `MM YYYY` | 〃 |
| B | `MM.DD` | `NONE-02-02` |

연·월·일이 **독립 채점**이라 확인된 필드만 채우는 편이 유리합니다.

## 3. 보조 경로 — `_fallback()`

주력 계단이 전부 실패한 이미지(약 2%)에만 돕니다. `src/pipeline.py`의
`DatePipeline`을 씁니다.

```
640px 축소
  → YOLOv8n 으로 날짜 영역 검출 (직접 학습, ONNX)
  → PP-OCRv3 det + 박스 사전 필터
  → PP-OCRv4 rec (한국어)
  → 인접 박스 병합 → 정규식 → 후보 선택
  → 실패 시 90° 회전 · 512/448/384px · 전처리 3종으로 재시도
```

박스 사전 필터는 rec을 돌리기 전에 영상 특징만으로 상위 K개를 고릅니다.
rec이 이 경로 비용의 80.9%를 차지하는데, det가 제안한 박스 26,499개 중
날짜가 파싱되는 건 0.63%(167개)뿐이라 넣은 장치입니다.

## 4. 모델 파일

전부 `weights/` 아래에 미리 받아 둡니다. **실행 중에는 절대 내려받지 않습니다**
(채점 환경이 오프라인이고, 자동 다운로드는 0점 사유입니다).

| 파일 | 크기 | 쓰는 곳 |
|---|---:|---|
| `rapidocr/PP-OCRv6_det_small.onnx` | 9.5MB | 1·2·5·6칸 |
| `rapidocr/PP-OCRv6_rec_small.onnx` | 20.3MB | 1~4칸 |
| `rapidocr/ch_ppocr_mobile_v2.0_cls_mobile.onnx` | 0.6MB | 방향 분류 |
| `rapidocr/PP-OCRv6_det_medium.onnx` | 59.2MB | 3·4칸 |
| `rapidocr/korean_PP-OCRv5_rec_mobile.onnx` | 12.9MB | 5칸 |
| `rapidocr/en_PP-OCRv5_rec_mobile.onnx` | 7.5MB | 6칸 |
| `yolo/date_v1.onnx` | 10.7MB | 보조 경로 (직접 학습) |
| `det/` `rec/` `cls/` (PaddleOCR) | 약 30MB | 보조 경로 |

주력 계단은 **약 121MB**, 보조 경로까지 더하면 약 151MB입니다.

`download_weights.sh`가 채점 전에 한 번 실행되어 이 파일들을 채웁니다.
**빌더 함수들은 파일이 없으면 `None`을 돌려주고**, 그 칸은 그냥 건너뜁니다.
전부 없어도 노트북은 죽지 않고 모든 행을 `NONE`으로 채워 정상 종료합니다.

> 개발 PC에서는 보조 경로용 PaddleOCR 모델이 `weights/` 가 아니라
> `C:\Users\Public\ocr_models` 에 있습니다. `eda/ocrlib.py` 가 그 경로를 보도록
> 되어 있어서 실험 스크립트는 그대로 돌아가지만, **제출 노트북은 `weights/` 만
> 봅니다.** 로컬에서 노트북을 통째로 시험할 때 보조 경로가 빠져 있을 수 있으니,
> 그 경우 `download_weights.sh` 를 먼저 돌리세요.

## 5. 출력 형식 — `to_row()`

```python
{"image_id": "000001", "year": "2027", "month": "06", "day": "26",
 "final_date": "2027-06-26"}
```

- `month`·`day`는 두 자리로 0을 채웁니다(`6` → `06`).
- 일부만 읽혔으면 그 필드만 채웁니다: `NONE-08-25`
- 셋 다 미검출이면 `final_date`는 단일 문자열 `NONE`입니다.
- CSV는 **`index=False`**로 저장합니다. 켜면 컬럼이 밀려 0점입니다.
